# 故事设计

## 开课卡与故事圣经

先从用户的原话提取意图：想体验什么身份、什么关系、什么情绪、什么类型的冲突。给出可修改的提案，而不是要求填写长问卷。

将以下信息写入 `bible`：

- `premise`：谁进入什么世界，为了什么目标，会遇到什么核心阻力。
- `canonPolicy`：原创 / 尊重原作的二创 / 平行世界 / 混合；用户锁定的设定与允许改动的部分。
- `worldRules`：年代、地点、组织、能力边界、代价、威胁来源。
- `protagonist`：姓名、身份、欲望、弱点、能力、入场方式和可成长空间。
- `cast`：角色的任务、动机、说话方式、关系；避免所有人同一口吻。
- `arc`：当前阶段的短程目标、承诺与暂定转折；不按学习片段数强行规定收束时间，未发生的剧情可改写。
- `timeline`：只记已经发生的事件；记录时间、地点、伤势、持有物等会影响连续性的事实。
- `openThreads`：已出现但未解决的线索、承诺、秘密和冲突。

故事框架与原文在当前模型内完成。每集更新发生的事与未解决线索；改设定时记录变更缘由。用户改变尚未实现的计划不需要重开课程，改动既定事件则明确视为修订或平行支线。

## 二创与原作事实

将“用户指定”“经核实的原作”“本课程原创 / 改编”分别标注在设定卡中。不确定的角色、组织、年代或能力先核实；能联网时使用可信原作来源并保留来源链接，无法核实时给出暂定设定，不把记忆或推测写成原作事实。只创作新的剧情与表达，引用用户提供的资料也须区别资料与课程原创。

例：用户提到“戴拿奥特曼、加入胜利队”。这表示题材和入队愿望，尚未明确原作组织名称、时间线和主角身份。“原著名”可能指原著人物或原创人物，应询问或给出暂定原创角色提案。在严格原作路线下先核实组织与时期；在用户认可的平行世界里可沿用其设定。不直接把这个例子写成固定课程。

## 每集的故事职责

一个完整章节或场景解决眼前任务，并产生下一步的代价或疑问；学习片段只须有行动、关系或理解的实际进展。用人物主动选择推动故事，避免只有景物介绍、能力展示或连续偶然事件。

按“主线 → 章节 → 场景 → 学习片段”组织：学习片段对应 200 / 500 词，serial 分别记录 arcId、chapterId、sceneId、segment 与 sceneStatus。具体局面、行动、阻力与结果可以分布在多个片段中；不要求每个片段都结束任务或制造反转。悬念来源是角色真正关心的问题，片段末也可自然停在情绪或动作上。

续写先列三项：上段停在哪里、主角这次选择什么、哪条已承诺线索能得到进展。未解决问题可以保留，但连续只增加谜题而不兑现会削弱追更；阶段性回答一件事，再让结果带出新的代价。例：新人保留自己的蓝卡，按房号找到真实队伍，兑现找队目标；红卡却不属于正常测试，于是团队开始核对来源。新悬念由这次选择和发现产生，不靠无关怪物突然出现。

用身份、持有物、位置、伤势、知识与时间检查连续性。角色说的话、主角猜测、行动验证的事实和未知真相分别记录；“门上有我的名字”不等于已证实那是自己的房间，“守卫说是测试门”不等于门内声音身份已确认。发现叙述冲突时修正正文，不能靠牵强解释去圆：例如先前守卫不笑，后文再写“他第一次不笑”就应改写具体新反应。

学习与故事相互配合：

- 先保证人物会这样说、事件会这样发生，再选择自然出现的语言目标。
- 难度靠句长、从句数量、表达频率和语境支持调整，不用生硬直译或不自然的简化英语。
- 把已学词放进不同角色、场景与句型，形成迁移；词汇复现不等于答题通过。
- 保留设定的能力边界与行动代价，让主角加入团队后有任务、合作与成长空间。
- 给未来语言扩展留 `profile.language`，不把英文特有的词数或语法解释硬套其他语言；非英语课程先约定计量单位。

## 连续性检查

续写前读取当前场景、上一片段摘要、人物状态和未解决伏笔。通过 bible 字段分页读取所需人物与事件，不把字段目录或首批记录视为完整设定。写后确认人物信息来源、时空衔接、行动代价与事实归属。

`bibleUpdate.timeline/worldRules` 数组追加去重；`cast/openThreads` 使用稳定 id 更新同一角色 / 线索，没有 id 的旧文本保留。伏笔用 status: resolved 标记解决，不能删除原承诺。记录实际发生的情节，不提前把计划写进时间线。
